## Bugs encontrados y corregidos (sesión 2)

### 1. DUPLICATE_POST destruía el estado (CORREGIDO)
- **Problema**: `publish.js` trataba el error 422/DUPLICATE_POST como `failed`, cuando en realidad el post YA existía en LinkedIn. Runs posteriores sobreescribían el status correcto.
- **Fix**: Si LinkedIn responde `DUPLICATE_POST`, el post se marca como `published` en lugar de `failed`.
- **Archivo**: `src/publish.js`

### 2. Race condition entre workflow runs (CORREGIDO)
- **Problema**: Un run de GitHub Actions hacía checkout de `main` con un `posts.json` desactualizado, re-publicaba posts ya publicados, y sobreescribía el commit del run anterior.
- **Fix**: Se agregó paso `git pull --rebase origin main` antes de ejecutar el publisher.
- **Archivo**: `.github/workflows/publish.yml`

### 3. Posts de prueba con status incorrecto (CORREGIDO)
- **Problema**: 3 posts de prueba aparecían como `failed` pero el log confirmaba que SÍ se publicaron en LinkedIn.
- **Fix**: Se restauraron a `published` con los datos reales del log (`publishedAt`, `linkedinPostId`).

## Troubleshooting rápido

- Si no corre automático:
  - Revisar que el workflow tenga `schedule` habilitado.
  - Revisar que la rama por defecto sea `main`.
- Si falla por credenciales:
  - Renovar token con `npm run token`.
  - Regenerar `LINKEDIN_CONFIG` con el nuevo `config.json`.
- Si falla por duplicado (`DUPLICATE_POST`):
  - Ya no debería ser problema (fix aplicado en `aedaa45`).
  - Si aún pasa: cambiar texto del post.
- Si hay conflicto de git en el workflow:
  - Ya no debería pasar (se agregó `git pull --rebase` en `aedaa45`).
